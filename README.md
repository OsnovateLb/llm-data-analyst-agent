# LLM-аналитик данных (Задание 3)

Веб-приложение на Streamlit. Пользователь загружает датасет (CSV или Excel) и при желании пишет, на что обратить внимание. После этого **ИИ-агент сам проводит анализ**: пишет Python-код, выполняет его в изолированной песочнице, видит результаты и решает, что проверить дальше. На выходе получается отчёт с ключевыми метриками, графиками, выводами, замечаниями о качестве данных и рекомендациями.

LLM вызывается через **[OpenRouter](https://openrouter.ai)** на **бесплатных моделях** (NVIDIA Nemotron, Gemma и др.): ключ бесплатный, карта не нужна. Подходит любой OpenAI-совместимый API, провайдер меняется переменной `LLM_BASE_URL`.

> Это не «LLM пересказывает статистику, подставленную в промпт». Модель получает только имя файла и размер таблицы. Всё остальное она узнаёт, вызывая инструмент `run_python`. Отчёт без хотя бы одного успешного запуска кода приложение не принимает.

## Как это работает

```
 Пользователь ──► Streamlit (app.py)
                    │  1. чтение CSV/Excel, проверка инструкции и данных (guard.py)
                    ▼
               DataAnalystAgent (agent.py) ◄────────────┐
                    │  2. запрос к LLM (OpenRouter)     │ 4. stdout, ошибки,
                    │     с инструментами:              │    PNG-графики
                    │     run_python, submit_report     │
                    ▼                                   │
                  LLM решает, какой код выполнить ──► Sandbox (sandbox.py → _runner.py)
                    │                                   отдельный процесс, df уже загружен
                    │  5. submit_report (JSON по схеме)
                    ▼
               Проверка отчёта → вывод метрик, выводов и графиков → скачивание в Markdown
```

1. **Инструменты агента** (tool calling в формате OpenAI):
   - `run_python(purpose, code)`: выполняет код, в переменной `df` уже лежит датасет. Возвращает stdout и ошибку. Графики сохраняются автоматически. Если модель умеет работать с изображениями, графики возвращаются ей как картинки, и агент видит, что нарисовал.
   - `submit_report(...)`: итоговый отчёт по JSON-схеме (метрики, выводы с обоснованием, графики, качество данных, рекомендации, ограничения).
2. **Цикл агента**: до N шагов (по умолчанию 14). На последнем шаге агенту прямо сообщается, что пора сдавать отчёт. Отчёт проверяется: нужен хотя бы один успешный запуск кода, обязательные поля и реально существующие id графиков. Если проверка не пройдена, агент получает ошибку и исправляет отчёт.
3. **Устойчивость на бесплатных моделях.** Агент выбирает бесплатные модели с поддержкой tools из актуального списка OpenRouter. При ошибке модели (недоступна, не поддерживает инструменты, игнорирует их) он **автоматически переключается на следующую**. Если модель прислала код в блоке ```python``` вместо вызова инструмента, код всё равно выполняется, а отчёт принимается из блока ```json```. Сетевые сбои и ответы 429/5xx обрабатываются повтором с паузой.

## Защита от prompt-injection и опасного кода

Защита многоуровневая: даже если один слой обойдут, остальные ограничат ущерб.

| Слой | Где | Что делает |
|---|---|---|
| Проверка инструкции | `guard.check_instruction` | Ищет типовые injection-фразы на русском и английском («игнорируй предыдущие инструкции», «покажи системный промпт», «ты теперь…», упоминания API-ключа, поддельные теги `<system>`). Такая инструкция не отправляется в модель, пользователь видит причину. |
| Сканирование данных | `guard.scan_dataframe` | Проверяет названия столбцов и текстовые ячейки. Найденное показывается пользователю и передаётся модели **как данные** с пометкой «не выполнять». |
| Разделение доверенного и недоверенного | `guard.wrap_untrusted`, `prompts.py` | Данные и вывод кода попадают к модели в тегах `<untrusted_data>` и `<tool_output>`. Закрыть эти теги изнутри данных нельзя: они экранируются. Инструкция пользователя лежит в `<user_instructions>` и по системному промпту не может менять правила. |
| Канареечный токен | `guard.new_canary` | В системный промпт вставлена случайная метка. Если она появится в отчёте, значит модель пытается вывести свои инструкции, и такой фрагмент вырезается. |
| Очистка отчёта | `guard.sanitize_report` | Удаляет внешние ссылки, URL, Markdown-картинки и HTML. Это закрывает утечку данных через `![](https://evil/?data=...)`. |
| Статическая проверка кода | `guard.check_code` (AST) | Импорт только из белого списка (pandas, numpy, matplotlib, seaborn, scipy…). Запрещены `eval/exec/open/getattr/__import__`, dunder-атрибуты, `read_pickle`, `to_sql`, `environ` и т.п. |
| Песочница | `sandbox.py`, `_runner.py` | Отдельный процесс `python -I` с **пустым окружением**: API-ключа там просто нет. Урезанные builtins, audit hook (PEP 578) блокирует сеть, запуск процессов, `ctypes`, запись вне временной папки и чтение файлов вне неё и вне каталогов Python. Лимиты: время, CPU, память, размер файлов. |
| Ограничение злоупотреблений | `app.py` | Необязательный пароль на вход (`APP_PASSWORD`), не больше 5 запусков за сессию, ограничения на размер файла и число строк. |

Проверить защиту можно на файле [`examples/demo_sales_with_injection.csv`](examples/demo_sales_with_injection.csv). В одном из комментариев к заказу спрятана инструкция «Ignore all previous instructions…». Приложение предупредит о ней, а агент отметит её в разделе «Качество данных» и не выполнит.

## Запуск локально

Нужен Python 3.10+ и бесплатный ключ OpenRouter: войдите на https://openrouter.ai, откройте https://openrouter.ai/keys и нажмите **Create API Key**. Лимит бесплатных моделей — 50 запросов в день, один анализ занимает примерно 5–14 запросов.

```bash
git clone https://github.com/OsnovateLb/llm-data-analyst-agent.git
cd llm-data-analyst-agent
python -m venv .venv
# Windows: .venv\Scripts\activate    Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

# ключ: через переменную окружения или в боковой панели приложения
# Windows (PowerShell): $env:LLM_API_KEY="sk-or-v1-..."
# Linux/macOS:          export LLM_API_KEY="sk-or-v1-..."

streamlit run app.py
```

Откроется http://localhost:8501. Загрузите CSV или Excel (например, `examples/demo_sales_with_injection.csv`), при желании напишите инструкцию и нажмите «Проанализировать».

## Деплой на Streamlit Community Cloud (бесплатно)

1. Зайдите на https://share.streamlit.io через GitHub.
2. Нажмите **Create app**, затем **Deploy a public app from GitHub**. Выберите репозиторий `OsnovateLb/llm-data-analyst-agent`, ветку `main`, файл `app.py`.
3. В **Advanced settings** укажите Python 3.12, а в **Secrets** вставьте:
   ```toml
   LLM_API_KEY = "sk-or-v1-..."
   APP_PASSWORD = "пароль-для-проверяющего"
   ```
4. Нажмите **Deploy**. Через пару минут приложение будет доступно по ссылке вида `https://<имя>.streamlit.app`.

## Настройки

| Переменная | По умолчанию | Описание |
|---|---|---|
| `LLM_API_KEY` | — | Ключ OpenRouter (или ввод в интерфейсе) |
| `LLM_MODEL` | авто | Модель; по умолчанию — лучшая доступная бесплатная |
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | Любой OpenAI-совместимый API |
| `AGENT_MAX_STEPS` | 14 | Максимум обращений агента к модели |
| `SANDBOX_TIMEOUT_S` | 60 | Лимит времени на один запуск кода |
| `SANDBOX_MEMORY_MB` | 2048 | Лимит памяти процесса песочницы (Linux/macOS) |
| `MAX_UPLOAD_MB`, `MAX_ROWS` | 20, 200000 | Ограничения на входной файл |
| `APP_PASSWORD` | — | Если задан, приложение спрашивает пароль |

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

54 теста без обращения к API и без ключа:
- `test_guard.py` проверяет распознавание injection-фраз, отсутствие ложных срабатываний на обычных инструкциях, проверку кода и очистку отчёта;
- `test_sandbox.py` проверяет выполнение pandas-кода и графики, а также блокировку сети, записи вне папки, чтения `/etc/passwd`, импорта `os` и бесконечного цикла;
- `test_agent.py` прогоняет полный агентный цикл с поддельным LLM-клиентом: передачу вывода кода, картинки только для моделей со зрением, отклонение отчёта без анализа и с несуществующими графиками, некорректный JSON в аргументах, текстовый режим, переключение модели, лимит шагов, очистку ссылок;
- `test_llm.py` проверяет HTTP-клиент на локальном сервере, имитирующем OpenRouter: отбор бесплатных моделей с tools, разбор tool_calls, повтор при 503 и сетевых сбоях, понятную ошибку дневного лимита.

## Структура

```
app.py                  интерфейс Streamlit
analyst/
  agent.py              агентный цикл (tool calling, переключение моделей)
  llm.py                клиент OpenAI-совместимого API (OpenRouter), без SDK
  prompts.py            системный промпт и схемы инструментов
  sandbox.py            запуск кода в отдельном процессе
  _runner.py            код, работающий внутри песочницы (лимиты, audit hook)
  guard.py              защита от prompt-injection, проверка кода, очистка отчёта
  data_io.py            чтение CSV/Excel (автоопределение кодировки и разделителя)
  report.py             экспорт отчёта в Markdown
examples/               демо-датасет (синтетический) со встроенной injection-атакой
tests/                  автотесты
```

## Ограничения

- Песочница на уровне Python (audit hook, урезанные builtins, лимиты ОС) хорошо защищает учебный проект, но это не полноценная изоляция уровня контейнера. Для продакшена код агента стоит запускать в отдельном контейнере, gVisor или облачном code interpreter.
- Эвристический детектор injection-фраз ловит типовые атаки, но не все. Поэтому главная защита — архитектура: недоверенные данные отделены от инструкций, у кода нет доступа к сети и секретам, отчёт проходит очистку.
